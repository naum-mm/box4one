# Local Telegram Bot API: установка, обновление и откат

## Архитектура и ограничения

Используется официальный [tdlib/telegram-bot-api](https://github.com/tdlib/telegram-bot-api),
commit `e3e9dd8e5b3d7ab8537cd5a10dc31d5ffa8f82d1`. Образ
`box4one-telegram-api:tdlib-e3e9dd8e5b3d` собирается из исходников с одним процессом
компиляции. Сборку лучше выполнять на рабочей машине, затем `docker save | ssh … docker load`:
компиляция C++ на production с 1 ГБ RAM может исчерпать память. Версия задана в Compose,
а не в `.env`. Для обновления источников измените SHA и тег вместе, пересоберите и повторите тесты.

Сервис `telegram-api` не публикует порт 8081. Он доступен боту через отдельную внутреннюю
сеть `telegram-private`; сеть egress нужна для соединений с Telegram. Каталог `./jobs`
смонтирован только на чтение по тому же абсолютному пути, что и у backend/worker.
Бот не получает файлового тома: backend проверяет владельца, TTL и канонический путь,
затем выдаёт `file:///data/ytdlp/jobs/...` исключительно по внутреннему API.
Данные Telegram лежат в `./telegram-api-data`, владелец `65532:65532`, права 0700.
Не удаляйте этот каталог при обновлении. Сервер запущен без root и capabilities,
с read-only корнем, автоматическим перезапуском и HTTP healthcheck без секретов.

Telegram документирует [загрузку до 2000 MB и передачу локальных путей](https://core.telegram.org/bots/api#using-a-local-bot-api-server).
BOX4ONE использует консервативный предел **2 000 000 000 байт** на отдельный файл;
`TELEGRAM_LOCAL_UPLOAD_LIMIT_BYTES` позволяет только уменьшить его. В облачном режиме
сохраняется предел 49 000 000 байт. Backend проверяет реальный размер на диске до передачи.
Лимит всего задания `MAX_JOB_GB` продолжает учитывать промежуточные файлы: файл ниже
лимита Telegram всё равно может не поместиться в лимит задания или свободный диск.

Для MP3 используется sendAudio, для MP4 — sendVideo с размерами изображения,
для прочих форматов — sendDocument. Файлы плейлиста отправляются отдельно через кнопки
файлов; ZIP остаётся резервной HTTPS-загрузкой. В облачном режиме загрузка идёт чанками
по 64 КиБ, в локальном — по URI без чтения файла ботом. Полных копий в RAM нет.

`telegram_deliveries` хранит попытку **до** HTTP-запроса. Успешно отправленный файл
повторно не загружается. После сетевого таймаута результат может быть неопределённым:
повторная кнопка даёт ссылку, а не вторую загрузку. Это предотвращает дубли ценой
отказа от автоматической повторной отправки при неопределённом результате.
Если отправка была пропущена только из-за размера (`fallback`), новая ручная попытка
может отправить файл после перехода с облачного лимита на Local API. Это не повтор
подтверждённой или неопределённой отправки: состояния `sent`, `sending` и `uncertain`
повторную загрузку блокируют.
429 повторяется максимум три раза, ожидание более 30 секунд переводит доставку в fallback.
Размер выше лимита и ошибки отправки дают HMAC-подписанную HTTPS-ссылку с прежним TTL,
проверкой владельца и срока хранения. Ссылка — временный bearer-доступ, её нельзя публиковать.

При полном отказе Local API невозможно немедленно отправить даже текст этим же
сервером. Бот не выполняет скрытый вход в облако и не создаёт второй polling-процесс:
неподтверждённое обновление остаётся за durable cursor и после восстановления приводит
к HTTPS-fallback. Утверждать немедленную доставку ссылки во время полного отказа нельзя.
Для длительного отказа используйте явный откат в облачный режим ниже.

## Настройки и активация

Добавьте в существующий `.env`, не меняя остальные секреты:

```dotenv
# Значение создаётся установщиком и хранится только в закрытом .env.
TELEGRAM_ACTIVATION_WORD=
TELEGRAM_API_ID=
TELEGRAM_API_HASH=
TELEGRAM_LOCAL_API_URL=http://telegram-api:8081
TELEGRAM_LOCAL_API_ENABLED=false
TELEGRAM_LOCAL_UPLOAD_LIMIT_BYTES=2000000000
TELEGRAM_API_MEMORY=256m
TELEGRAM_API_SWAP=512m
```

Собственные API ID и API hash получите через [my.telegram.org → API development tools](https://core.telegram.org/api/obtaining_api_id).
Это отдельные credentials приложения, не Bot Token. Нельзя использовать чужие или примерные значения.
Права `.env` — 0600; не выводите `docker compose config`, inspect окружения или ответы Telegram с токенами в общий журнал.
Для проверки Compose используйте `docker compose config --quiet`.

Бот публичен: `/start` показывает инструкцию без кодового слова. До активации доступны
только приветствие и ввод слова. Правильное слово записывает активацию в MariaDB,
неправильное — не открывает доступ. После пяти попыток в десятиминутном окне действует
блокировка до окончания окна. Счётчик и активация сохраняются после перезапуска.
`TELEGRAM_ALLOWED_USERS` остаётся для совместимости старых идентификаторов, но больше
не разрешает и не ограничивает доступ. Даже старые пользователи должны активироваться.
Отключение `telegram_users.enabled` отзывает доступ и подписанные ссылки;
повторная миграция больше не включает отключённых пользователей автоматически.

После активации доступны 🎬 Скачать видео, 🎵 Скачать аудио, 📋 Мои задания и ℹ️ Информация,
кнопки 1080p/720p/480p и MP3 320/128, команды, статус и редактируемый прогресс.
Существующие задания, очередь, MariaDB и HTTPS не меняются.

## Безопасное обновление

1. Сравните установленный код, main и PR; сохраните незакоммиченные изменения.
2. Соберите backend и telegram-bot и проведите тесты **до** остановки приложения.
3. Дождитесь отсутствия queued/downloading/processing заданий. Остановите worker,
   затем bot/backend/cleanup на короткое окно; nginx и MariaDB можно оставить.
4. Создайте backup: `python3 scripts/manage.py --target /opt/ytdlp-web backup`.
   Архив содержит `.env`, nginx, исходники и согласованный SQL dump. Храните его вне установки с 0600.
   При наличии готовых файлов используйте `backup --include-files` или отдельно сохраните jobs.
5. Проверьте восстановление SQL в изолированной временной MariaDB без портов и сети.
   Сравните таблицы, количество jobs/files/users/requests и базовые агрегаты.
   Сохраните image ID старых контейнеров под rollback-тегами.
6. Замените только управляемые исходники существующего каталога. Не копируйте `.env`,
   nginx/nginx.conf, jobs, mariadb/data и сертификаты из Git. Запишите развернутый SHA.
7. `python3 scripts/configure.py init`; `docker compose config --quiet`.
8. Выполните `docker compose run --rm --no-deps backend python -m app.telegram_migrate`.
   Миграция добавляет две таблицы; jobs/files и старые таблицы не изменяет.
9. `docker compose up -d --no-deps --wait backend telegram-bot`;
   запустите ранее остановленные worker/cleanup. Проверьте health, HTTPS и число заданий.

Если API credentials ещё нет, оставьте `COMPOSE_PROFILES=telegram` и
`TELEGRAM_LOCAL_API_ENABLED=false`: активация и новый механизм доставки работают в
облачном режиме, локальная отправка больших файлов **ещё не включена**.
Запуск без Telegram: пустой COMPOSE_PROFILES; backend и веб-интерфейс работают как прежде.

## Переключение действующего бота

До включения убедитесь, что образ telegram-api собран и доступен на FINN,
API ID/hash заполнены и резервная копия восстановлена в проверочной базе.

```sh
cd /opt/ytdlp-web
python3 scripts/telegram_local.py local
```

Скрипт создаёт постоянный каталог, запускает API и проверяет HTTP, затем останавливает
старый poller, проверяет отсутствие webhook, вызывает облачный **logOut**, меняет
профили и адрес, проверяет getMe и запускает один бот. Он не вызывает
`drop_pending_updates`. Offset принадлежит очереди конкретного сервера: после остановки
старого poller и успешного getMe на новом сервере прежнее значение сохраняется в
закрытый `.telegram-transport-cursors.json`, а cursor новой очереди начинается с 0,
чтобы не подтвердить её непрочитанные события чужим offset. При обычном перезапуске
сервера или бота cursor не сбрасывается; он продолжает храниться в MariaDB. HTTP healthcheck не подтверждает
валидность API ID/hash; фактическая авторизация проверяется getMe после logOut.
При неудаче после logOut не запускайте облачную копию параллельно: исправьте credentials
и повторите getMe локально либо выполните процедуру отката с учётом десятиминутного окна.

По [правилам Telegram](https://core.telegram.org/bots/api#logout) после logOut
вход в облако недоступен 10 минут. На старте бот никогда автоматически не вызывает logOut.
Аренда polling хранится в MariaDB, продлевается каждые 20 секунд и живёт 90 секунд;
второй процесс не получает аренду. SIGTERM завершает задачи и освобождает собственную аренду.

## Проверка и ресурсы

```sh
docker compose config --quiet
docker compose --profile telegram-local ps
docker compose exec telegram-api telegram-bot-api --version
free -m
swapon --show
docker stats --no-stream
df -h /
```

Один worker; лимиты MariaDB 128 МБ, backend 128 МБ, bot 192 МБ, Local API 256 МБ,
worker 384 МБ и proxy 64 МБ — это потолки, а не гарантированное суммарное потребление.
На 1 ГБ RAM параллельная обработка и передача требуют реальных измерений; 2 ГБ является
исходной целью, не подтверждённой гарантией. Не понижайте лимиты до постоянного OOM.
Логи Docker ограничены 2 × 5 МБ, файлы BOX4ONE очищаются прежним TTL. Встроенное
состояние Telegram не чистите вручную во время работы: следите за размером
`du -sh telegram-api-data` и свободным местом, локальные URI позволяют избежать
multipart-копии исходного файла. Завершённые временные каталоги сборки можно удалить отдельно.

Автотесты на синтетических данных:

```sh
docker compose -p box4one-telegram-tests -f tests/compose.telegram.yaml up -d --wait db
docker compose -p box4one-telegram-tests -f tests/compose.telegram.yaml build tests
docker compose -p box4one-telegram-tests -f tests/compose.telegram.yaml run --rm tests
```

Проверки 51/101/2000 MB в unit-тестах проверяют выбор транспорта и лимит;
это **не** реальные отправки. Для приёмки нужны разрешённые MP3/MP4 >50 и >100 МБ,
проверка получения пользователем, рестарты обоих сервисов, недоступность API, fallback,
TTL, чужой файл и замеры RAM/CPU на FINN. Не отправляйте тесты посторонним пользователям.

## Откат

При работающем Local API сначала:

```sh
python3 scripts/telegram_local.py cloud
```

Скрипт останавливает bot, вызывает logOut на локальном сервере, останавливает API,
ждёт 10 минут, возвращает облачный профиль, проверяет getMe и безопасно начинает
чтение новой облачной очереди перед запуском bot, архивируя прежний cursor.
Если Local API недоступен, не делайте принудительный cloud login: сначала восстановите
локальный сервис для корректного logOut. Telegram не гарантирует сохранность обновлений
при двух одновременных серверах.

Для отката кода остановите bot/backend, восстановите управляемые исходники и Compose
из `source/` backup, прежний `.env` и nginx-конфигурацию. Используйте сохранённые образы
`box4one-backend:rollback-telegram-local` и `box4one-telegram-bot:rollback-telegram-local`
через временный compose override или верните их теги latest. Запустите только прежние
сервисы, проверьте HTTPS и задания. Добавленные таблицы совместимы со старым кодом:
не удаляйте их и не восстанавливайте старый SQL поверх новых пользовательских данных.
SQL dump нужен для восстановления при повреждении базы; сначала сохраните текущее состояние.
Не выполняйте `down -v` и не удаляйте production volumes.
