# Проверки Telegram-интеграции

## Автоматизированные проверки

| Набор | Количество |
|---|---:|
| Повторная настройка и сохранение секретов | 3 |
| Обновление, архивы, восстановление и удаление | 14 |
| Защитный HTTP/CONNECT-прокси | 6 |
| API, MariaDB, ACL, миграции, конкурентные запросы и квоты | 23 |
| Команды и обработчики aiogram со stub Telegram session | 19 |
| Размеры MP4, поворот, повреждённые заголовки | 4 |
| Проверка URL и классификация ошибок DNS | 3 |
| Взаимодействие backend/proxy/worker | 6 |
| Worker: обработка аудио, запрет сетевого FFmpeg и браузерный транспорт | 5 |

Основной набор: **72 теста**. Дополнительные наборы: **6** и **5**.
Они проверяют подпись/TTL/ZIP, изоляцию пользователей, повторные update/callback,
уведомления, offset/lease, потерю связи и совместимость существующего web/worker API.
Реальные Telegram-сообщения не входят в эти автоматические тесты.

Проверки жизненного цикла выполняются во временных каталогах с синтетическими
настройками/историей и подменёнными вызовами Docker: сохранение данных при
обновлении, отказ при активной загрузке, остановка без удаления, проверяемый архив
перед purge, отмена удаления при ошибке дампа, восстановление SQL до старта
приложения и отклонение небезопасных архивов. Эти тесты не удаляют действующую
установку. При изменении скриптов отдельно пройдены 17 проверок настройки и
жизненного цикла; неизменённые API/bot/proxy-наборы повторно не запускались.

## Браузерный транспорт источников

В образ worker включён официальный extra `pin-curl-cffi` той же версии yt-dlp.
Некоторые extractors сами запрашивают браузерный TLS/HTTP-транспорт: без curl_cffi
они могут получать HTTP 410 ещё при открытии страницы. Глобальный режим
`--impersonate` не включается, исходный URL не переписывается приложением.

`tests/check_worker_runtime.py` запускается в образе worker, подключённом к его
обычной приватной сети с download-proxy. Проверяется наличие доступного транспорта,
публичный HTTPS-запрос через прокси и отказ 403 для внутренних адресов. Проверки
локального преобразования и запрета сетевых протоколов FFmpeg также сохраняются.
Конкретные ссылки проверяются отдельно без включения их содержимого в отчёты.

## Регрессия проверки адреса

Backend находится в приватной сети. Проверка публичного домена через его локальный
resolver ошибочно отклоняла корректные URL. Теперь `URL_VALIDATION_PROXY` направляет
проверку к существующему download-proxy: внутренний метод CHECK получает только
схему, имя хоста и порт, без пути и параметров исходной ссылки.

Прокси проверяет все DNS-адреса и отвечает 204 для публичного назначения, 403 для
запрещённого, 422 для несуществующего домена и 503 при временном сбое DNS. Backend
отличает отказ в URL от временной недоступности проверки. Worker по-прежнему
повторно проверяет и фиксирует адрес каждого сетевого соединения, включая переходы
и медиа-сегменты. DNS-проверка до создания jobs не заменяет эту защиту.

Регрессионный сценарий проверяет настоящий POST /drafts из приватной сети backend:
публичный URL принимается, loopback отклоняется. Дополнительные проверки подтверждают,
что CHECK не открывает соединение с целевым сайтом и не передаёт путь/query.

## Остальные проверки

Сборки образов, повторная CLI-миграция, оба Nginx-шаблона, конфигурации Compose,
компиляция Python и проверка diff выполнены. Исправленный tmpfs-монтаж проверен
запуском контейнера не от root.

Приёмка настоящего обмена с Telegram и конкретных видеоисточников выполняется
отдельно с разрешением владельца. Автоматические проверки не являются разрешением
на merge, миграцию или развёртывание production.

## Общая веб-очередь

Проверяется создание заданий через веб и Telegram в одной БД, единая нумерация
очереди, общий просмотр задания, веб-скачивание и потоковый ZIP из Telegram-задания.
TTL и авторизация очереди сохраняются. Telegram API скрывает чужие задания,
а веб-доступ по случайному коду следует обычным правилам BOX4ONE.

## Единая конфигурация и история

Проверяется создание полного единого .env, сохранение секретов при повторной
настройке, валидация истории и дубликатов ключей. Справка использует заданные
лимиты и сроки хранения. Telegram показывает только последние 10 заданий,
старые ожидающие уведомления сохраняются, веб-история остаётся полной.
