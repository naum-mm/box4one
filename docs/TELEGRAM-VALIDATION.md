# Проверки Telegram-интеграции

## Пройдено: 46 тестов

| Набор | Количество | Что проверено |
|---|---:|---|
| `test_deployment.py` | 3 | Установка, повторная настройка, сохранение HTTPS/секретов |
| `test_download_proxy.py` | 4 | Частные адреса, DNS, CONNECT, перенаправления |
| `test_telegram_api.py` | 18 | Реальная отдельная MariaDB, миграция, конкуренция, лимиты, ACL, подпись/TTL/ZIP, уведомления, lease, web/worker API |
| `test_telegram_bot.py` | 14 | aiogram Dispatcher со stub Telegram session, команды, форматы, ошибки, загрузка/ссылки, retry_after, потеря связи и восстановление уведомлений |
| `check_telegram_runtime.py` | 5 | Живые backend/proxy/worker: health, scoped token, блокировка внутренних адресов, публичный HTTPS, обработка задания |
| `check_worker_runtime.py` | 2 | Локальная конвертация синтетического аудио и запрет сетевого FFmpeg |

Основной набор: **39/39**; отдельные runtime-наборы: **5/5** и **2/2**.
Все данные синтетические, тесты используют отдельные сеть, MariaDB и volume.
Реальные Telegram-запросы не выполнялись.

## Дополнительные проверки

- Собраны образы tests, backend, download-proxy, telegram-bot и worker.
- Backend и proxy запущены в отдельной тестовой сети; worker получает и завершает
  задания через обычный API. У небезопасного задания backend сохраняет failed.
- Прокси отклоняет внутренние адреса и успешно выдаёт README из разрешённого
  GitHub-репозитория по HTTPS. Произвольные внешние видео для проверки не скачивались.
- CLI `python -m app.telegram_migrate` выполнен дважды на тестовой MariaDB.
- Импорт бота в его настоящем контейнере выполнен без токена и без polling.
- `nginx -t` прошёл для обоих шаблонов с синтетическим TLS-сертификатом.
- Синтаксическая компиляция Python и `git diff --check` прошли.
- Compose configuration проверена без Telegram, с Telegram, для unit- и runtime-окружений.

Тесты ограничены по памяти/CPU и запускаются последовательно с безопасным запасом
RAM/swap. Проблема DNS-заглушки, затрагивавшей соединения тестовой БД, исправлена:
подменяется только функция валидации URL. Проверка публичной выдачи использует
существующее соединение с БД вместо открытия дополнительного.

## Что остаётся непроверенным

Настоящий Telegram-токен не предоставлен; полный сценарий с настоящими сообщениями,
Telegram rate limits и реальной сетью Telegram проверяется после отдельного
разрешения на запуск. Совместимость конкретных видеоисточников с прокси требует
приёмочного прогона на нужных владельцу ссылках.

Production-миграция, deployment, merge, auto-merge и release не выполнялись.
Резервная копия и особенности рабочего окружения должны проверяться перед
согласованным развёртыванием. Эксплуатационные сведения сервера остаются в приватном
отчёте владельцу.
