# Проверки Telegram-интеграции

## Автоматизированные проверки

| Набор | Количество |
|---|---:|
| Установка и повторная настройка | 3 |
| Защитный HTTP/CONNECT-прокси | 6 |
| API, MariaDB, ACL, миграции, конкурентные запросы и квоты | 19 |
| Команды и обработчики aiogram со stub Telegram session | 17 |
| Размеры MP4, поворот, повреждённые заголовки | 4 |
| Проверка URL и классификация ошибок DNS | 3 |
| Взаимодействие backend/proxy/worker | 6 |
| Локальная обработка аудио и запрет сетевого FFmpeg | 2 |

Основной набор: **52 теста**. Дополнительные наборы: **6** и **2**.
Они проверяют подпись/TTL/ZIP, изоляцию пользователей, повторные update/callback,
уведомления, offset/lease, потерю связи и совместимость существующего web/worker API.
Реальные Telegram-сообщения не входят в эти автоматические тесты.

## Регрессия проверки адреса

Backend находится в приватной сети. Проверка публичного домена через его локальный
resolver ошибочно отклоняла корректные URL. Теперь `URL_VALIDATION_PROXY` направляет
проверку к существующему download-proxy: внутренний метод CHECK получает только
схему, имя хоста и порт, без пути и параметров исходной ссылки.

Прокси проверяет все DNS-адреса и отвечает 204 для публичного назначения, 403 для
запрещённого, 422 для несуществующего домена и 503 при временном сбое DNS. Backend
отличает отказ в URL от временной недоступности проверки. Worker по-прежнему
повторно проверяет и фиксирует адрес каждого сетевого соединения, включая переходы
и медиа-сегменты. DNS-проверка до создания jobs не заменяет эту защиту.

Регрессионный сценарий проверяет настоящий POST /drafts из приватной сети backend:
публичный URL принимается, loopback отклоняется. Дополнительные проверки подтверждают,
что CHECK не открывает соединение с целевым сайтом и не передаёт путь/query.

## Остальные проверки

Сборки образов, повторная CLI-миграция, оба Nginx-шаблона, конфигурации Compose,
компиляция Python и проверка diff выполнены. Исправленный tmpfs-монтаж проверен
запуском контейнера не от root.

Приёмка настоящего обмена с Telegram и конкретных видеоисточников выполняется
отдельно с разрешением владельца. Автоматические проверки не являются разрешением
на merge, миграцию или развёртывание production.
