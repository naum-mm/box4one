# Установка и обслуживание BOX4ONE

## Требования

Ubuntu 24.04 LTS, amd64 или arm64, systemd, root, доступ к GitHub, репозиторию
Docker и реестру образов. Нужны `curl`, домен с корректными A/AAAA и входящие
TCP 80/443. DNS и firewall скрипт не меняет. Shared hosting без Docker не подходит.
Docker Engine и Compose устанавливаются из официального репозитория Docker,
если Docker ещё отсутствует. Конфликтующие пакеты не удаляются автоматически;
у существующего Docker должен работать `docker compose`.

Рекомендуется минимум 2 ГБ RAM и диск от 20 ГБ. Работа на 1 ГБ RAM требует
настроенного swap от 2 ГБ и ограничений ресурсов из `.env`; сборка занимает
несколько минут. Скрипт не создаёт swap и не меняет системную память. Проверяйте
`free -h` и `df -h`: свободное место должно покрывать `MAX_JOB_GB`, `MIN_FREE_GB`,
остальные результаты, резервную копию и сборку образов. Размер задания включает
временные файлы; промежуточные данные могут быть больше итогового результата.

## Единая точка входа

Каждый раз скачивайте актуальный скрипт. Он получает код из ветки `main` GitHub
и выполняет выбранное действие. Рабочий каталог — `/opt/ytdlp-web`.

```bash
curl -fsSL https://raw.githubusercontent.com/naum-mm/box4one/main/bootstrap.sh -o /tmp/box4one.sh
sudo bash /tmp/box4one.sh install video.example.com
```

Домен задаётся без схемы, порта и пути, ASCII или punycode. Для совместимости
прежний вызов только с доменом также означает `install`. Установка требует
отсутствующий каталог. Повторный запуск `install` не перезаписывает его: после
сбоя исправьте причину и запустите локальный `sudo ./install.sh video.example.com`
из проекта. Секреты и уже созданная БД сохранятся.

Создаются `.env` с новыми секретами (0600), каталоги данных, HTTP-конфигурация
Nginx и маркер установки. Собираются образы, запускается MariaDB, выполняется
повторяемая миграция, затем запускаются сервисы. Telegram по умолчанию выключен.
Проверка HTTP: `curl --fail http://video.example.com/health`.

## Настройки

Единственный рабочий файл — `/opt/ytdlp-web/.env`.
Полный перечень с начальными значениями: [`.env.example`](../.env.example).
Не копируйте заглушки паролей из примера в рабочий файл.

| Настройки | Значение |
|---|---|
| `DOWNLOAD_ACCESS_WORD`, `QUEUE_ACCESS_WORD` | Разные пароли скачивания и очереди |
| `MAX_JOB_GB`, `MIN_FREE_GB`, `DISK_CHECK_SECONDS` | Лимит задания, резерв диска (ГиБ), период проверки |
| `VIDEO_PLAYLIST_LIMIT`, `AUDIO_PLAYLIST_LIMIT` | Максимум элементов плейлиста |
| `JOB_TTL_MINUTES`, `CLEANUP_INTERVAL_SECONDS` | Срок хранения результата и интервал очистки |
| `COMPOSE_PROFILES=telegram` | Включение бота после заполнения Telegram-параметров |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_INTERNAL_TOKEN`, `TELEGRAM_ALLOWED_USERS` | Токен бота, отдельный внутренний секрет, разрешённые ID |
| `TELEGRAM_PUBLIC_URL` | Публичный HTTPS-адрес для ссылок |
| `TELEGRAM_HISTORY_LIMIT` | Число заданий в Telegram (по умолчанию 10); веб-история полная |
| `TELEGRAM_UPLOAD_LIMIT_BYTES`, `TELEGRAM_LINK_TTL_SECONDS` | Размер прямой отправки и срок подписанной ссылки |
| `*_MEMORY`, `*_SWAP`, `SERVICE_CPU_LIMIT` | Ограничения ресурсов контейнеров |
| `COMPOSE_PROJECT_NAME`, `*_NETWORK_*` | Имена проекта и сетей; сохраняйте существующие при обновлении |

Формат `ИМЯ=значение`, без кавычек и shell-команд. Проверка:
`python3 scripts/configure.py check`, затем `docker compose config --quiet`.
Обычные настройки применяются через `docker compose up -d --wait`; `restart`
новые переменные не применяет. Перед пересозданием worker дождитесь окончания
загрузок. Для включения Telegram используйте управляемое обновление ниже:
оно выполняет миграцию до старта polling.

Повторная настройка добавляет недостающие значения и сохраняет имеющиеся секреты.
Пароли MariaDB в `.env` действуют при первичной инициализации; изменение строки
не меняет пароль существующего пользователя БД. Смена паролей доступа/токенов
может сбросить сессии. Внутренние пути и API заданы согласованно в Compose.
`frontend/config.js` содержит переключатель интерфейса воспроизведения.

## HTTPS

Настройте DNS и работающий HTTP. Если Certbot отсутствует:

```bash
sudo apt update && sudo apt install -y snapd
sudo snap install --classic certbot
cd /opt/ytdlp-web
sudo ./enable-https.sh
```

Certbot запросит email и согласие. Скрипт настроит сертификат, проверит Nginx,
установит hook перечитывания сертификатов и проверит продление. Сертификаты
хранятся вне проекта в `/etc/letsencrypt`; этот каталог не входит в архив проекта.
Проверка: `curl --fail https://video.example.com/health`.

## Обновление

После скачивания актуального `bootstrap.sh`:

```bash
sudo bash /tmp/box4one.sh update
```

Скрипт проверяет маркер и принадлежность контейнеров, отказывается прерывать
активную загрузку, останавливает приложение, оставляя БД и прокси, и создаёт
проверенный архив. Затем обновляет управляемые исходники, дополняет `.env`,
собирает образы, выполняет миграцию и запускает сервисы с проверкой готовности.
`.env`, локальный `nginx/nginx.conf`, база `mariadb/data`, результаты `jobs`
и каталог проверки сертификатов сохраняются. Локальные изменения управляемого
кода заменяются версией из GitHub. Установка не требует ручного `git pull`.

Если резервное копирование не удалось, прежние сервисы запускаются обратно.
Если последующий шаг не удался, архив сохраняется; прочитайте ошибку и исправьте
причину, затем повторите `update`. Автоматически заменять БД старой копией нельзя:
это могло бы потерять новые задания. Для ручного отката архив также содержит
предыдущие исходники, когда имеется Git или манифест установленных файлов.
Дампы содержат секреты и историю: не публикуйте их.

## Резервная копия и восстановление

```bash
sudo bash /tmp/box4one.sh backup
sudo bash /tmp/box4one.sh backup --include-files
```

Архивы: `/var/backups/box4one/box4one-*.tar.gz`, права 0600, каталог 0700.
Включены `.env`, действующий Nginx и SQL-дамп всей базы (история веба/Telegram,
настройки интеграции и состояние уведомлений). Обычный онлайн-дамп транзакционно
согласован; скачанные файлы при работающей очереди могут меняться. Для согласованной
копии с файлами сначала дождитесь окончания заданий и остановите worker/cleanup.
Без `--include-files` история сохраняется, а сами готовые файлы в архив не входят.
Сроки TTL при восстановлении не продлеваются; истекшие ссылки не оживают.
Храните дополнительную копию вне сервера. Старые архивы автоматически не удаляются.

Восстановление допускается только в отсутствующий каталог проекта:

```bash
sudo bash /tmp/box4one.sh restore /var/backups/box4one/ARCHIVE.tar.gz
```

На чистой Ubuntu скрипт подготовит Docker, установит актуальный код из `main`,
восстановит настройки и SQL до запуска приложения, выполнит миграцию и запустит
сервисы. Если архив содержал `jobs`, восстановит и файлы. Архив должен быть
доверенным: он содержит SQL и настройки. Приложение не работает со старой копией
поверх действующей базы. При переносе HTTPS на другой сервер заранее перенесите
**весь** `/etc/letsencrypt` с правами и ссылками; он не входит в резервную копию.
После восстановления выполните `enable-https.sh` для установки hook и проверки
продления. На том же сервере сертификаты после удаления проекта сохраняются.

## Удаление и диагностика

[Режимы удаления](UNINSTALL.md) используют тот же скачанный скрипт.
Docker, общие образы, сертификаты и чужие проекты автоматически не удаляются.

```bash
cd /opt/ytdlp-web
sudo ./scripts/diagnose.sh
sudo ./scripts/logs.sh worker -f
sudo ./scripts/queue-errors.sh
```

Одна очередь для веба и Telegram, поиск ошибки — по коду задания.
[Диагностика](../scripts/README.md), [Telegram](TELEGRAM.md).
Образ включает yt-dlp, Node.js и curl_cffi; FFmpeg/ffprobe работают с локальными
файлами, сетевые загрузки идут через проверяющий прокси. Версия yt-dlp и её
curl_cffi extra зафиксированы в `worker/Dockerfile`; обновление зависимостей
требует пересборки. Доступность источника зависит от yt-dlp, сети и самого источника.
