# Диагностика ytdlp-web

Запускать от root или пользователя с доступом к Docker. Нужны Python 3, Bash, Docker Compose и `free`. Скрипты определяют папку проекта по своему расположению; текущая папка терминала не важна. Команды только читают состояние, не перезапускают сервисы и не удаляют файлы.

```bash
cd /opt/ytdlp-web
./scripts/diagnose.sh
./scripts/logs.sh                     # все сервисы за час, до 200 строк на сервис
./scripts/logs.sh worker -f           # следить за воркером; Ctrl+C для выхода
./scripts/logs.sh backend --since 24h --tail 1000
./scripts/queue-errors.sh             # последние 20 записей БД с ошибками
./scripts/queue-errors.sh 280nt12m5c   # статус, ошибка из БД и логи задания
./scripts/queue-errors.sh 280nt12m5c --since 168h --tail 10000
```

Имена сервисов: `all`, `mariadb`, `backend`, `nginx`, `worker`, `cleanup`.

В проекте одна общая очередь. Поиск «по имени очереди» выполняется по коду задания (`job_code`): 10 латинских букв/цифр из интерфейса. Имена контейнеров передавать вместо кода не нужно. Для логов контейнера используется `logs.sh` с именем сервиса.

Диагностика показывает свободное место, память, состояния контейнеров, healthcheck, OOMKilled, доступность внутреннего HTTP API backend, проверку конфигурации Nginx и число заданий по статусам. Она не проверяет публичный DNS, внешние firewall и доступность внешних источников. Код выхода 0 означает успешную базовую проверку, 1 — проблему; подробности смотрите в выводе.

Ошибки читаются напрямую из БД через запущенный backend, поэтому backend и MariaDB должны работать. При ошибке доступа к БД поиск по коду всё равно пытается прочитать контейнерные логи. Статусы выводятся как сохранены в БД, время БД — UTC. Для traceback показываются две строки перед совпадением и до 40 строк после него; соседние строки могут относиться к другим событиям.

По умолчанию поиск ограничен последними 24 часами и 3000 строками каждого сервиса. Отсутствие совпадений не означает, что ошибки не было: логи могут быть старее, ротированы или потеряны при пересоздании контейнера. `--since` и `--tail` расширяют поиск только по сохранившимся логам. Для `queue-errors.sh` код выхода сообщает об успешности чтения, а не о наличии ошибок задания.

Скрипты не печатают .env и не передают пароли в аргументах процессов. Сами логи могут содержать URL, названия файлов и сообщения удалённых сервисов; учитывайте это перед пересылкой вывода.

## Telegram (необязательный)

Диагностика отличает отключённый бот от отсутствующего обязательного сервиса.
Логи: `./scripts/logs.sh telegram-bot -f` либо
`docker compose --profile telegram logs --tail=100 telegram-bot`.
Не публикуйте токены и временные ссылки. См. [руководство Telegram](../docs/TELEGRAM.md).
